# 提问与用户输入

`ask` 在桌宠旁显示问题、快捷选项及自由输入框，并等待用户实际回答。适用于需要补充信息或分支选择的任务，不必为每个普通动作都提问。

```json
{
  "action": "ask",
  "question": "接下来先处理哪一项？",
  "options": ["整理文件", "检查连接"],
  "durationMs": 60000
}
```

问题长度 1–1000；选项最多 5 个，每个长度 1–100。`options` 可省略或为 `[]`，表示主要使用自由输入。即使提供选项，用户仍可输入其他答案；不能把选项当作严格枚举约束。

`durationMs` 为整数，范围 1000–120000，默认 60000 毫秒。批次的剩余有效时间必须覆盖等待时长和排队时间，否则命令可能先因到期被取消。

## 根据回执分支

将需要决策的 `ask` 放在该批次最后一步，或独立成批。收到对应步骤 `outcome:"completed"` 且存在真实 `answer` 后，再创建下一批。协议没有条件表达式；不要把所有候选操作都排在 `ask` 后面让客户端依次执行。

MCP 从 `pet_execute` 的回执取得回答，HTTP 查询原命令回执。Anelf Agent 也从关联 MCP 的工具结果取得回答，频道正文仅用于话语，不额外发送回执事件。`results` 按已尝试的步骤顺序排列，回答在对应 `ask` 的结果中，不一定是 `results[0]`。

超时返回 `failed`，不提供默认答案；用户停止或拖动可能返回 `cancelled`；执行器失联可能返回 `unknown`。这些状态都不能当作用户同意。没有有效回答时暂停依赖该回答的后续步骤，并按实际状态简短说明。

如果问题是对外部操作的确认，回答只适用于当前明确描述的操作，不应被扩大为对无关任务的授权。
