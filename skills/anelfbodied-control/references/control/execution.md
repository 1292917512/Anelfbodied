# 批次、回执与恢复

## 构造批次

以下是生成命令的 JavaScript 示例，运行后再将求值所得对象交给 MCP 或 HTTP；不要把表达式原样写入 JSON：

```js
const batch = {
  protocol: 'desktop-pet/1',
  id: crypto.randomUUID(),
  session: crypto.randomUUID(),
  expiresAt: Date.now() + 120000,
  commands: [{ action: 'say', text: '我在这里。', durationMs: 2000 }],
};
```

`id` 和 `session` 允许字母、数字、点、下划线、冒号、连字符，长度 1–100。MCP/HTTP 可为一项逻辑任务生成一个 `session`，多个批次共用它以便整体取消；Anelf 频道必须使用本轮客户端注入的 `session`。

每批 1–16 步，待执行批次最多 32 个，全局串行执行。`expiresAt` 是 Unix 毫秒时间，接收时必须在未来且最多五分钟；它同时约束排队与运行时间。为动作时长总和、用户回答和合理排队留出余量，长流程拆批，不提交有效期不足的等待。

批次与动作对象不接受未声明字段。`returnReceipt` 是可选的批次字段，只决定 Anelf 频道是否回传事件；不影响 MCP/HTTP 回执的产生或查询。

## 阅读回执

| `status`    | 含义与后续                                     |
| ----------- | ---------------------------------------------- |
| `accepted`  | 已受理并保存，尚未确认执行；继续等待或查询     |
| `running`   | 执行中；继续等待或按需求取消                   |
| `completed` | 本批所有动作已完成                             |
| `cancelled` | 已取消或到期，保留已完成步骤                   |
| `failed`    | 某步失败，例如提问超时；后续步骤不执行         |
| `unknown`   | 无法确认执行结果；检查后再决定后续，不自动重放 |

`completed` 是确认完成的步骤数，`total` 是原批次步骤数，`results` 按尝试顺序记录每一步的 `outcome`、可选 `answer` 和 `detail`。取消时可能只有前几步的结果，不能把缺少的步骤视为完成，也不能把整批一概当成未发生。

`pet_state` 和 HTTP 查询仅提供回执，不会重新执行命令，也不提供桌面画面。列表最多最近 100 条，已知 ID 应直接查询该 ID。

## 去重与断线

提交前保留完整原批次。相同来源下相同 ID 和相同规范化内容返回已有回执，不重复执行。重试时连同 `expiresAt`、`session`、动作顺序一起保持不变；同 ID 改内容会返回 `id_conflict`。

网络异常后先查询原 ID。若确认未受理且仍在有效期内，可以重发完整原批次。查询暂时不可用时先恢复连接，不换 ID 绕过去重；过期后需重新判断任务是否仍需执行，不机械地延期重试。`unknown` 必须结合实际情况核对，重新发送同 ID 也不会修复未知结果。

HTTP 与 MCP 共用外部命令身份；Anelf 频道来源另行隔离。不能用 MCP 空查询证明频道动作未发生。回执去重有保留窗口：终态记录在命令到期 24 小时后可回收，容量上限 2000 条 / 8 MB；不要把很久以前的旧命令当成可以安全重放的新任务。

## 取消与接管

取消一个批次：

```json
{ "id": "task-command-id" }
```

取消自己持有的整个任务会话：

```json
{ "session": "task-session-id" }
```

MCP 使用 `pet_cancel`，HTTP 使用 `POST /v1/cancel`。同时提供 `id` 和 `session` 时按两者共同筛选，不是分别取消两组任务。不同 Agent 的 MCP 会话共用外部命令空间，只取消自己任务的标识。

取消返回前会等待实际动作收束，保留部分回执。若返回空数组，说明没有匹配的活动任务，不表示指定任务从未执行；再查询原回执。取消 session 会拦截该 session 五分钟内的迟到命令，后续新任务使用新 session。

SDK 显式取消、用户点击停止、用户拖动与连接中断不是同一事件：SDK 取消针对对应工具调用；用户拖动接管当前本机动作；界面停止还会请求当前 Anelf 会话收束。网络断开不证明已经取消。执行器失联或取消未获确认可返回 `unknown`，按未知状态报告，不伪装成成功。

用户要求停止时取消自己的活动批次并核对终态；需要停止远端 Anelf 推理时另用[频道管理](connection.md)的 `stop`。用户已接管或取消后，不自行重新安排同一动作。
