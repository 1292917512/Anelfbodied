# 控制协议

协议版本：`desktop-pet/1`。字段规范以 `src/protocol/schema.ts` 为唯一声明源，HTTP、MCP 和 Anelf 适配器使用同一份校验。

## 动作

| 动作    | 参数                                                                | 默认时长 |
| ------- | ------------------------------------------------------------------- | -------- |
| `say`   | `text`：1–4000 字；`durationMs`：300–60000                          | 6000 ms  |
| `emote` | `name`：neutral、happy、thinking、sleepy、surprised；时长 100–30000 | 2000 ms  |
| `move`  | `x/y`：当前工作区可用范围中的 0–1 坐标；时长 100–10000              | 1000 ms  |
| `ask`   | `question`：最多 1000 字；`options`：最多 5 项；时长 1000–120000    | 60000 ms |

`ask` 完成时 `results` 含用户的真实 `answer`。超时为失败，不生成虚构回答。动作不支持执行代码、任意系统输入或文件操作。

每批必须提供 `id`、`session`、`expiresAt` 和 `commands`。ID 允许字母、数字、点、下划线、冒号、连字符，最长 100。有效期在接收后的五分钟以内，每批最多 16 步，全局最多 32 个待执行批次，顺序执行。

## 端点

| 方法                | 路径               | 返回                                          |
| ------------------- | ------------------ | --------------------------------------------- |
| GET                 | `/v1/capabilities` | 能力和动作 JSON Schema                        |
| POST                | `/v1/commands`     | 202 与当前回执；受理不代表完成                |
| GET                 | `/v1/receipts/:id` | 指定回执                                      |
| GET                 | `/v1/receipts`     | 最近最多 100 条                               |
| POST                | `/v1/cancel`       | `{id}` 或 `{session}`；等待实际停止后返回回执 |
| POST / GET / DELETE | `/mcp`             | MCP 会话与工具协议                            |

MCP 最多 16 个会话，每会话最多 32 个并发请求，闲置 15 分钟释放。正常退出的调用方应终止 MCP 会话。HTTP 和 MCP 使用相同命令身份；Anelf 按频道地址、用户和会话隔离。

## 回执与取消

回执包含 `status`、`completed`、`total`、逐步 `results` 和更新时间。状态为 `accepted`、`running`、`completed`、`cancelled`、`failed`、`unknown`。

- 受理先落盘，随后才能执行。相同来源、相同 ID 和相同规范化内容返回已有结果；同 ID 不同内容返回 409。
- 取消保留已完成步骤，排队任务立即取消，运行任务等待渲染器确认。取消整个 session 会阻止该 session 五分钟内的迟到指令；新任务使用新 session。
- 渲染器一秒内未确认取消时，主进程重置它并返回 `unknown`。崩溃、重启或持久化失败不会伪装成成功，也不会自动重播。
- 用户拖动会接管当前本机动作。普通触碰反馈与 AI 动作独立。
- 回执不是“用户已经阅读”的证明；它记录客户端执行与确认的事实。

回执文件上限 2000 条 / 8 MB，完成记录在命令到期 24 小时后回收；达到容量时拒绝新任务，不提前淘汰仍有效的去重记录。去重保障有明确时间窗口，不能用新 ID 盲目重试 `unknown` 的操作。

Anelf SSE 重连只补显示历史。完整终止帧缺失时客户端保留不确定状态，点击停止与服务端同步。动作回执回传使用稳定的 `receipt-<id>` 消息 ID；问答自动回传，其他批次按 `returnReceipt` 决定，避免无条件确认循环。
